# Standard object baseline

One JSON file per standard object under `objects/`, shape `StandardObjectJson` in `src/types.ts`.
A retrieve from a real org only contains *customisations* of standard objects, so the standard
fields themselves must be known up front.

Generated by `scripts/gen-baseline` (`pnpm baseline:gen`) from the vendored sf-skills `enterprise_api`
snapshot (Apache-2.0, Copyright (c) 2026 Salesforce, Inc., revision
`4bbae5c421e51b40e4169afa72c4496372a602a7`, see `scripts/gen-baseline/source/sf-skills/VENDOR.md`) and
a facts-only extraction of the public Object Reference PDF (Last-Modified Fri, 09 Oct 2026 22:12:36 GMT,
see `scripts/gen-baseline/source/object-reference/VENDOR.md`). Do not edit `objects/*.json` or
`PROVENANCE.json`; put hand facts in `scripts/gen-baseline/overrides.json`, v1.0 facts live in
`scripts/gen-baseline/v1-pins.json`, migration exceptions in `scripts/gen-baseline/diff-allowlist.json`.
CI fails when the files differ from regeneration (`pnpm baseline:check`). `standardValueSets.json`
stays hand-maintained.

Rules:
- Do not list the system fields `Id`, `IsDeleted`, `CreatedDate`, `CreatedById`,
  `LastModifiedDate`, `LastModifiedById`, `SystemModstamp`, or `OwnerId`; the loader adds them.
- `nillable`, `createable`, `updateable` default to `true`; set them only when `false`.
- Lookups: `referenceTo` + `relationshipName` (parent side) + `childRelationshipName`
  (the name the parent uses for the child list, e.g. `Contacts` on Account).
- Picklists backed by a StandardValueSet name it in `standardValueSet`; the values live in
  `standard/standardValueSets.json`. Picklists added by the generator carry no values: standard
  picklist values are per org.
- Compound fields: list the compound field with type `Address`/`Name` and each component
  with `compoundFieldName` set.
- Fields that exist only when an org feature is enabled carry `featureGated: true` and are always
  nullable; describe does not show the tag.
- `ownerTargets` (object level) narrows `OwnerId.referenceTo`; absent means User and Group. The
  generator writes it only when the sources name a narrower target set; an owner target outside
  User/Group or no stated target is a hand decision in `overrides.json` (Event, Group, ServiceContract).
- Documented fields of an unsupported type or with a reference target outside the object list are
  skipped; `PROVENANCE.json` lists them.
- Fields known only from the sf-skills `field_reference` table are emitted read-only
  (`createable: false`, `updateable: false`).
- Provenance per fact is in `PROVENANCE.json`; `verified` means the two sources agree, not that a
  live org was compared.
