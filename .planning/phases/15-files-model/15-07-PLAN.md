Facts verified at planning time (do not re-derive):
- `deleteBatch(client, session, obj, work, globals, deleting)` (engine.ts:~881-916) walks `schema.childRelationships(obj.name)`:
  restrict -> error; cascade -> nested `this.deleteBatch(childObj, childWork, globals, new Set([...deleting, ...ids]))`
  (bypasses `refuse()`, so ContentVersion's `deletable: false` does not block the cascade); otherwise
  `UPDATE <child> SET <fk> = NULL WHERE <fk> = ANY($1)` for ALL matching child rows.
- Pitfall 1: cascading ContentDocument -> ContentVersion runs that set-null branch for the child relationship
  `ContentDocument.LatestPublishedVersionId -> ContentVersion` and nulls the pointer on the documents being deleted.
- `undeleteBatch` (:~918-937) restores `cascadeDelete` children with `IsDeleted = true`; no change needed.
- Cascade flags from plan 15-03: ContentVersion.ContentDocumentId, ContentDocumentLink.ContentDocumentId and
  ContentDocumentLink.LinkedEntityId are `deleteConstraint: "Cascade"`.
- ContentDocumentLink flags: createable, updateable, deletable true; undeletable false (Supported Calls). ShareType is
  restricted (V/C/I) and required; Visibility restricted (AllUsers/InternalUsers/SharedUsers). ContentDocumentId and
  LinkedEntityId are not updateable (create-only, D-14).
- `refuse()` (engine.ts:148) answers `INVALID_TYPE_FOR_OPERATION` for a disabled object operation;
  `Errors.restrictedPicklist` gives `INVALID_OR_NULL_FOR_RESTRICTED_PICKLIST`; `Errors.notWritable` gives
  `INVALID_FIELD_FOR_INSERT_UPDATE`.

Decisions written into this plan:
- Undelete of links is supported through the ContentDocument (and linked-record) cascade only; direct undelete stays refused
  because the Object Reference's Supported Calls for ContentDocumentLink list no undelete() (Open Question 2: source wins).
- Duplicate links (same document, same entity) are not refused in Phase 15 (no documented error text; no unique index).
- A direct update of `ContentDocument.Title` is a plain document-only update (the field is updateable on ContentDocument);
  it does not propagate to the version. Documented gap, pinned by a test.
- Mirrored fields on update: only `Title` can change on a version after insert (FileType/FileExtension/ContentSize/PathOnClient are not updateable), so the update mirror triggers on `Title`.
- SOQL is not used in these tests for ContentDocumentLink (its mandatory-filter rule arrives in plan 15-08); use `engine.retrieve` / raw SQL.
