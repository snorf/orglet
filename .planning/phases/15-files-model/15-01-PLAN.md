- `FieldType` union: packages/metadata/src/types.ts:11-38. `sqlTypeFor` (packages/schema/src/columns.ts) is an exhaustive
  switch without default (adding the member forces a compile error there). Same for `describeType` (packages/api/src/describe.ts:9)
  and the formula value-type switch (packages/formula/src/values.ts:~25-58, `Address`/`Location` return `"Unknown"`).
- packages/formula/src/compile.ts:241 refuses a `LongTextArea` field reference with `fieldNotFound(...)`; a Base64 field must
  be refused the same way (Salesforce formulas cannot read binary fields).
- packages/metadata/src/build.ts:~300-375 has a per-type switch applying load-time defaults; `LongTextArea`/`Html` set
  `sortable = false; groupable = false; filterable = false` (line ~342). Base64 gets the same three.
- `Store.storedFields(obj)` (packages/engine/src/store.ts:21) = `obj.fields.filter((f) => !isVirtual(f))`; `selectList`,
  `insert`, `update` all iterate it.
- `coerceValue(field, raw)` (packages/engine/src/coerce.ts:~20-117) switches on `field.type`; text-like types fall into a
  default branch with a length check (`STRING_TOO_LONG`) that must NOT apply to Base64.
- `Errors` factory: packages/engine/src/errors.ts:29; `saveError(statusCode, message, fields)` helper. `Errors.invalidType(label, field, value)`
  yields `INVALID_TYPE_ON_FIELD_IN_RECORD`.
- `MAXIMUM_SIZE_OF_DOCUMENT` is a member of the partner-WSDL StatusCode enum (research, LOW confidence on the binding to
  ContentVersion); no Salesforce document names an error for an oversized JSON blob body (D-05 fallback applies: message
  prefixed `UNSUPPORTED:content-size`).
- Limits (D-05, research): REST "Insert or Update Blob Data" allows 50 MB of base64 text / 37.5 MB decoded for a
  non-multipart insert. orglet reads MB as MiB (lenient reading; record this in a code comment):
