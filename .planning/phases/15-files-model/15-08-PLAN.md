Decisions written into this plan:
- Error text (third-party report, MEDIUM-LOW; errorCode MALFORMED_QUERY documented):
  `Implementation restriction: ContentDocumentLink requires a filter by a single Id on ContentDocumentId or LinkedEntityId using the equals operator or multiple Id's using the IN operator.`
- orglet always enforces the rule (Salesforce lifts it with the "Query All Files" permission from API 59.0; orglet has no permission model). Comment it at the check.
- Guarantee test (planner's algorithm, deterministic and testable): evaluate the WHERE chain as a boolean expression in which every
  qualifying condition is `false` and every other condition, and every NOT-ed operand, is `true` (AND binds tighter than OR,
  parentheses from openParen/closeParen). If the expression is `true`, rows could match without a qualifying filter -> reject.
  Qualifying = field (alias stripped, case-insensitive) is `Id`, `ContentDocumentId` or `LinkedEntityId`; operator `=` with a
  non-NULL literal, or `IN` with a value list or a semi-join. `!=`, `NOT IN`, `LIKE`, ranges, `= null` do not qualify. No WHERE -> reject.
- Base64 select: the select item is the row id (`${alias}."id"`), the shape builds the URL; when the id is null (parent absent) the value is null.
  A blob URL is returned for every live version even when no bytes are stored (blob presence is the BlobStore's business; the download answers 404, plan 15-09).
- WHERE/ORDER/GROUP refusal: `new SoqlError("INVALID_FIELD", \`\nfield '${field.name}' can not be filtered, sorted or grouped in a query call\`)`
  (Salesforce wording for filter is "field 'X' can not be filtered in a query call"; one message for the three clauses is orglet's choice).
