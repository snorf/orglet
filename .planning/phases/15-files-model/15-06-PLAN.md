<objective>
Implement the ContentVersion insert semantics in the engine (FILE-03, FILE-04, FILE-05, FILE-09 store side): a files step
inside `saveBatch` that takes `VersionData` out of the row (D-04), derives the system fields (D-08, D-09, D-12),
creates or versions the ContentDocument and mirrors it (D-11), auto-links `FirstPublishLocationId` (D-10) and writes the
bytes through the BlobStore, all inside the per-record savepoint. Off in import mode except for storing supplied bytes.

Purpose: the core of "files work as in a real org".
Output: packages/engine/src/files.ts, engine.ts call sites, files.test.ts, InlineBlobStore DB tests.

Decisions written into this plan:
- The files step is plain functions in files.ts taking `(client, store, ...)`, not engine privates and not a TriggerExecutor
  (hooks have no PoolClient; D-03 wants `mirrorDocument` callable outside DmlEngine, e.g. a Phase 17 stub-document path).
- `DmlEngine` gets `readonly blobs: BlobStore` and `EngineOptions.blobs?: BlobStore` (default `new InlineBlobStore(this.store)`):
  this is the seam Phase 17/18 plug the external store into (D-13).
- A ContentVersion insert without VersionData is allowed (no document rule names it required; ContentUrl versions exist):
  Checksum/ContentSize stay null, FileExtension from PathOnClient when present, FileType from the table. Its download answers
  404 (plan 15-09) — this is the D-13 "inline version with no bytes" path.
- The FirstPublishLocationId link is created only when the insert creates the document (a later version does not add a
  second link; "exactly one", D-10).
- Version number: `max` of the numeric VersionNumbers of the document's versions + 1, computed after `SELECT ... FOR UPDATE`
  on the document row, so concurrent inserts for one document cannot share a number.
- New document row: Id = pre-assigned `generateId("069")` (the ContentDocument key prefix from the schema object), OwnerId =
  the version's OwnerId, audit stamps = the version's, IsDeleted false, Title = the version's Title; everything else via
  `mirrorDocument`. PublishStatus/MalwareScanStatus stay null (no source for a value; research Pitfall 5: note, do not invent).
- The engine never reads blob bytes back; `w.file.blob` is released (set to undefined) after `put`.
