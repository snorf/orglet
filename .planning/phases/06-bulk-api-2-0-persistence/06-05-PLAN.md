<objective>
Move Bulk API 2.0 query jobs onto the Postgres store with the persisted lifecycle (D-13), keep
every Heimdall-relevant results behaviour (D-20), and replace the `/\(\s*select\b/i` regex with the
AST rule set from 06-02 (D-15, D-17). After this plan the in-memory `JobStore` is gone.

Planning-time decisions (locked):
- `QueryJob` becomes the persisted shape: drop `header` and `rows`; add `errorMessage?: string`.
  Delete `JobStore` from jobs.ts.
- Request order in POST /jobs/query: (1) `parseBulkQuery(soql)` (parse failure -> SoqlError
  MALFORMED_QUERY via the central handler); (2) `bulkQueryViolation(query, ctx.engine.schema)` ->
  `sendErrors(reply, 400, [apiError("FEATURE_NOT_ENABLED", violation.message)])`; (3)
  `compileSoql(soql, { schema: ctx.engine.schema, orgSchema: ctx.engine.orgSchema, includeDeleted: operation === "queryAll" })`
  so a bad field throws SoqlError (400 INVALID_FIELD) before a row exists; (4) create the row at
  `UploadComplete`; (5) `setState(... "InProgress")`; (6) run all pages with `runQuery` exactly as
  today (batchSize 2000), flatten with the existing `flattenHeader`/`flattenRow`; (7) one
  `withTransaction(ctx.engine.pool, async (client) => { await store.writeQueryResults(client, id, header, rows); await store.setState({ kind: "query", id, to: "JobComplete", totalProcessingTime }, client); })`;
  (8) respond `queryJobInfo` of the re-read row. A thrown error in (6)/(7): `req.log.error(err)`,
  `setState(... "Failed", errorMessage: \`InternalServerError : ${(err as Error).message}\`)`, respond 200
  with the Failed job info.
- Object name: `ctx.engine.schema.getObject(query.sObject ?? "")?.name ?? query.sObject ?? ""`
  (the regex `/\bfrom\s+.../` goes too).
- Results paging: `locator` accepted only when `/^\d+$/`, else offset 0 (today's tolerance);
  `maxRecords` accepted only when `/^\d+$/` and > 0, else all rows. Store reads
  `LIMIT max + 1` to know whether more rows exist; `Sforce-Locator` = `String(offset + page.length)`
  when more exist, else the literal `null`; `Sforce-NumberOfRecords` = `String(page.length)`.
  Results are served for any state (unchanged; a non-JobComplete job simply has no rows).
- Query job info adds `errorMessage` only when set (query JobInfo documents no such field; it is
  emitted only for Failed jobs).
- Abort: `CLIENT_SETTABLE` check (only `Aborted` is meaningful for query jobs; `UploadComplete` ->
  `InvalidJobState : unsupported state UploadComplete`); `setState(... "Aborted")` false -> 400
  INVALIDJOBSTATE with message `Aborting already Completed Job not allowed` when the job is
  JobComplete (guide, "Abort a Query Job"), else `InvalidJobState : cannot abort a job in state ${job.state}`.
- Delete: `deleteJob("query", id, DELETABLE.query)` false -> 400 `InvalidJobState : cannot delete a job in state ${job.state}`.
- Query rows inserted in blocks of 1000 with `jsonb_array_elements ... WITH ORDINALITY`.
- Intra-plan note: Task 1 trims `QueryJob` and deletes `JobStore`, so `pnpm build` fails until
  Task 2; Task 1 verifies with vitest only.

Output: query half of store.ts (+ tests), query handlers rewritten, regex retired, new bulk.test.ts tests.
