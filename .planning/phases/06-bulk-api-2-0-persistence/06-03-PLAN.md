<objective>
Create the Postgres storage foundation for Bulk API 2.0 jobs in the `_orglet` schema and wire it
into `orglet up` and `orglet reset`: table DDL, the single guarded state writer, boot
reconciliation, the 7-day retention purge and the per-org drop. Pure SQL over `_orglet`; no route
changes (plans 06-04/06-05 move the routes onto this).

Planning-time decisions (locked):
- Four tables (research Pattern 1, simplified): `bulk_ingest_jobs` keeps the raw uploaded CSV in
  one `csv_data text` column (no `input_header`/`input_row_count` columns: every result read
  re-parses `csv_data` with the job's own delimiter); `bulk_ingest_results` holds only
  `(row_index, success, record_id, created, error)`; `bulk_query_jobs` holds `result_header jsonb`;
  `bulk_query_rows` holds `cells jsonb` (array of strings) per 0-based `row_index`. Both child
  tables reference their job with `ON DELETE CASCADE`. Every table is keyed by `org_schema` first
  (D-01, same as `_orglet.key_prefixes`).
- Retention basis `created_date` for every state (D-18; Limits Quick Reference "Batch and job
  lifespan", Bulk API 2.0 column: "Jobs in a terminal state ... that are older than seven days are
  deleted. Jobs in a non-terminal state that are older than seven days are periodically cleaned
  up."). Window literal `interval '7 days'`, no env var or option (D-11).
- Transition table (D-08), in `jobs.ts`:
  ingest: Open -> [UploadComplete, Aborted]; UploadComplete -> [InProgress, Aborted, Failed];
  InProgress -> [JobComplete, Failed].
  query: UploadComplete -> [InProgress, Aborted, Failed]; InProgress -> [JobComplete, Failed, Aborted].
  `CLIENT_SETTABLE = {UploadComplete, Aborted}`. Documented delete states (research Pitfall 6):
  `DELETABLE.ingest = [UploadComplete, JobComplete, Aborted, Failed]`, `DELETABLE.query = [JobComplete, Aborted, Failed]`.
- Locked restart messages (D-07, D-16; orglet's wording, Salesforce-style `Code : text`):
  `BULK_INGEST_RESTART_MESSAGE = "ServerRestarted : The server restarted while this job was in progress. Records already processed are listed in successfulResults and failedResults; records not yet processed are listed in unprocessedrecords."`
  `BULK_QUERY_RESTART_MESSAGE = "ServerRestarted : The server restarted while this job was in progress. No results were saved; create a new query job to run the query again."`
  (Query results and the JobComplete transition are written in one transaction in 06-05, so a
  reconciled query job has no rows. Ingest chunks commit atomically with their results, 06-01/06-04,
  so the ingest message needs no "may have been committed" caveat.)
- Boot log lines (only when non-zero), `up()` style:
  `bulk: marked ${n} job(s) left in progress by a previous run as Failed` and
  `bulk: purged ${n} job(s) older than 7 days`. Reset log line (always):
  `dropped ${n} bulk job(s) for schema "${c.orgSchema}"`.
- `ApiOptions`/`ApiContext` stay unchanged (D-04); tests call `prepareBulk` themselves.

Output: `packages/api/src/bulk/schema.ts`, `schema.test.ts`, `jobs.ts` additions, api barrel
exports, CLI wiring.
</objective>
