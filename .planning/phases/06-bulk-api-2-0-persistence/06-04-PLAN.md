<objective>
Move Bulk API 2.0 ingest jobs from the in-memory `JobStore` to the `_orglet` tables through a new
`BulkStore`, with per-chunk atomic persistence on the engine seam from 06-01, truthful
`unprocessedrecords`, the guarded state machine and the per-request retention purge. Query jobs
stay on the in-memory map until 06-05 (same file, sequential plan).

Planning-time decisions (locked):
- `IngestJob` (jobs.ts) becomes the persisted application shape: drop `csvChunks`, `inputHeader`,
  `successRows`, `failedRows`; add `errorMessage?` (already there). `JobStore` keeps only
  `readonly query = new Map<string, QueryJob>()` until 06-05 deletes it.
- Result rows: `{ rowIndex, success, recordId, created, error }`. Success row CSV:
  `[recordId ?? "", String(created ?? false), ...inputRow]`; failure: `["", error ?? "", ...inputRow]`
  (same as today's `formatSaveError` text). `created` is `true` for insert, `false` for update and
  delete, `r.created ?? false` for upsert (unchanged logic).
- Counters: per chunk `number_records_processed += chunk.length`, `number_records_failed += failed`
  in the same transaction as the result rows (final values equal today's).
- Failure inside processing (any thrown error): the failing chunk rolls back with its transaction;
  the job moves InProgress -> Failed with `errorMessage = \`InternalServerError : ${(err as Error).message}\``,
  `req.log.error(err)`, and the PATCH answers 200 with the Failed job info (Salesforce reports
  job-level failure as job state). Empty header keeps today's text
  `InvalidBatch : the uploaded CSV had no header row` (InProgress -> Failed).
- Relationship-column rows (`UNSUPPORTED:bulk-relationship-column`, unchanged text) are written in
  200-row chunks through `withTransaction(ctx.engine.pool, (client) => store.writeIngestChunk(client, ...))`
  (no engine call).
- Purge: a shared `preHandler` on every `/jobs/*` route (ingest and query) calling
  `store.purgeExpired()` (route option `{ preHandler: purgeExpired }`, not a global hook, so other
  routes are untouched).
- Upload while not Open stays 400 `InvalidJobState : batches can only be added while the job is Open (is ${state})`;
  UploadComplete from a wrong state stays `InvalidJobState : cannot move to UploadComplete from ${state}`;
  abort refusal stays `InvalidJobState : cannot abort a job in state ${state}`; delete refusal stays
  `InvalidJobState : cannot delete a job in state ${state}`, now with DELETABLE.ingest
  (UploadComplete, JobComplete, Aborted, Failed); any other requested state stays
  `InvalidJobState : unsupported state ${String(state)}`. All with errorCode `INVALIDJOBSTATE`, HTTP 400.
- Pool discipline (D-19, pglite-socket): no pool client is held while another is used. Autocommit
  `pool.query` for single statements; only `engine.transaction` / `withTransaction` hold a client,
  and inside them only `tx.client` / `client` is used.
- Intra-plan note: Task 1 trims `IngestJob`, so `pnpm build` fails on `routes/bulk.ts` until Task 2
  lands; Task 1 verifies with vitest only (esbuild, no type-check). Task 2 restores `pnpm build`.

Output: store.ts + store.test.ts, ingest routes on the store, bulk.test.ts setup, new
bulk-persistence.test.ts (per-chunk and result-CSV blocks).
</objective>
