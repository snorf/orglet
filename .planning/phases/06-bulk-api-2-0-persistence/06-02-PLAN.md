<objective>
Build the Bulk API 2.0 query restriction check as a pure, AST-based module beside the Bulk code
(D-15), with the locked rejection wording (D-17) and the guide's literal compound-field rule
(D-18). Route wiring (replacing the `/\(\s*select\b/i` regex) happens in plan 06-05.

Planning-time decisions (locked):
- Dependency: add `"@jetstreamapp/soql-parser-js": "^8.1.0"` to `packages/api/package.json`
  `dependencies` (same range as `packages/soql`; lockfile already resolves 8.1.0) and commit the
  updated `pnpm-lock.yaml`. Do NOT re-export `parseQuery` from `@orglet/soql` (research
  "Alternatives Considered": keeps `@orglet/soql` untouched).
- Rejection wording (D-17, recorded as orglet's own, undocumented by Salesforce): message
  `Bulk API 2.0 query jobs do not support <construct>`, where `<construct>` is exactly one of:
  `TYPEOF`, `GROUP BY`, `OFFSET`, `aggregate function <NAME>` (NAME upper-cased, e.g. `COUNT`),
  `FIELDS()`, `parent-to-child relationship subqueries`, `compound field <path>` (path as written
  in the query, e.g. `BillingAddress` or `Account.BillingAddress`). errorCode is applied by the
  route (`FEATURE_NOT_ENABLED`), not here.
- Check order (first violation wins): walk `query.fields` in select order — `FieldTypeof` ->
  TYPEOF; `FieldSubquery` -> subquery; `FieldFunctionExpression` with functionName `FIELDS` ->
  FIELDS(); functionName in {COUNT, COUNT_DISTINCT, SUM, AVG, MIN, MAX} (case-insensitive) ->
  aggregate; `Field` / `FieldRelationship` resolving to type `Address` or `Location` -> compound;
  then `query.groupBy !== undefined` -> GROUP BY; then `query.offset !== undefined` -> OFFSET.
  Do NOT use the parser's `isAggregateFn` flag (it is also true for CALENDAR_YEAR and other date
  functions, which are legal). WHERE semi-joins (`valueQuery` on a condition) are NOT rejected.
- Unknown fields/relationships are not this module's concern: return no violation and let
  `compileSoql` report `INVALID_FIELD` later.
- Parse failure: `parseBulkQuery` throws `malformed(detail)` from `@orglet/soql` (SoqlError
  `MALFORMED_QUERY`, mapped to 400 by the central error handler), like REST.

Output: `packages/api/src/bulk/soql-rules.ts`, `packages/api/src/bulk/soql-rules.test.ts`, the
dependency line and lockfile.

    ```typescript
    /**
     * Bulk API 2.0 query jobs accept a narrower SOQL than REST: the guide lists TYPEOF, GROUP BY,
     * OFFSET, aggregate functions, compound address/geolocation fields, FIELDS() and parent-to-child
     * relationship queries as unsupported. The check walks the parser's AST beside the Bulk code so
     * REST SOQL (the @orglet/soql compiler) can never drift when these rules change. Salesforce
     * documents the list but not the error shape, so the message wording is orglet's own.
     */
    import { parseQuery, type FieldType, type Query } from "@jetstreamapp/soql-parser-js";
    import type { OrgSchema } from "@orglet/metadata";
    import { malformed } from "@orglet/soql";

    export type BulkRuleSchema = Pick<OrgSchema, "getField" | "resolveRelationship">;
    export interface BulkQueryViolation { construct: string; message: string }

    const AGGREGATES = new Set(["COUNT", "COUNT_DISTINCT", "SUM", "AVG", "MIN", "MAX"]);
    const COMPOUND_TYPES: ReadonlySet<string> = new Set(["Address", "Location"]);

    export function parseBulkQuery(soql: string): Query { try { return parseQuery(soql); } catch (err) { throw malformed((err as Error).message); } }
    export function bulkQueryViolation(query: Query, schema: BulkRuleSchema): BulkQueryViolation | undefined { ... }
    ```

For `Field` (`type: "Field"`) use `schema.getField(sObject, field.field)` and report `field.field`.
