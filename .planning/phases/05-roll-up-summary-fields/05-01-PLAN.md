<objective>
Lay the metadata contracts for roll-ups and make the SFDX reader parse `Summary` fields instead of
dropping them (ROLL-01, parsing half), plus the pure filter-value tokenizer the resolver in 05-02
uses (ROLL-03, value encoding half).

Purpose: every later plan builds against `RollupDef` / `FieldDef.rollup`; defining it first stops
executors from inventing shapes. The resolver (D-05..D-08) is plan 05-02; this plan keeps the
observable behaviour of `buildOrgSchema` unchanged for Summary fields (skip + `UNSUPPORTED:field-type`
warning, moved from sfdx.ts to build.ts) so the tree stays green between plans.

Planning-time decisions (do not relitigate):
- No `"Summary"` member in `FieldType` (would break the exhaustive switches in `formula/src/values.ts`
  `sfTypeOf`, `describeType`, `sqlTypeFor`). Only `SourceField.type` widens to `FieldType | "Summary"`;
  a resolved roll-up becomes an ordinary Number/Currency/Percent/Date/DateTime `FieldDef` carrying `rollup`.
- `summaryOperation` is stored raw on SourceField and normalised (case-insensitive, upper-case) by the resolver.
- Filter values: comma lists split outside double quotes; blank (`<value/>`, absent, all-whitespace) means "blank" (`[]`).

Output: types, Summary parsing, `packages/metadata/src/rollup.ts` with the tokenizer, tests.
</objective>

    /**
     * Roll-up summary resolution helpers. Metadata writes roll-up references as dotted `Child.Field`

    /** Split `Child__c.Field__c`; anything but exactly one dot is not a roll-up reference. */
    export function splitRollupRef(ref: string): { object: string; field: string } | undefined {

      const [object = "", field = ""] = parts;
