<objective>
Resolve `Summary` SourceFields into stored, read-only `FieldDef`s carrying `rollup` (ROLL-01), enforce
the relationship rule (ROLL-02 with the D-05 whitelist, D-08 hard failure), and degrade everything
else with the three D-06/D-07 warning areas. Replaces 05-01's interim `UNSUPPORTED:field-type` skip,
which is what makes ROLL-09 (zero `field-type` warnings for Summary) true.

Purpose: success criterion 1. Everything downstream (DDL, SQL builder, engine, describe) reads `FieldDef.rollup`.

Planning-time decisions (do not relitigate; recorded from 05-RESEARCH open questions and D-06 extensions):
- Check order per pending roll-up: (1) references resolvable (child object, FK on child pointing at this parent, summarized field, filter fields) else `rollup-target`; (2) relationship rule (MasterDetail or whitelist) else throw; (3) operation / summarized type / filters else `rollup-type` / `rollup-filter`; (4) chain wait. So an unresolvable child degrades and a resolvable plain lookup fails hard.
- `UNSUPPORTED:rollup-type` also covers SUM over a non-numeric field, an unknown/absent `summaryOperation`, and a formula or compound summarized field (extension of D-06, same area, no new area).
- `UNSUPPORTED:rollup-cycle` is a new, defensive area for roll-ups that summarise each other in a cycle.
- Precision: COUNT -> Number precision `sf.precision ?? 18`, scale `sf.scale ?? 0`. Numeric SUM/MIN/MAX -> child type, precision `sf.precision ?? Math.max(childPrecision ?? 18, 18)`, scale `sf.scale ?? childScale ?? 0` (avoids SUM overflow, 05-RESEARCH Pitfall 8). Date/DateTime carry no precision.
- Filter rules (05-RESEARCH §"Filter semantics", LOW items decided here): operators `equals, notEqual` for every allowed type; `lessThan, greaterThan, lessOrEqual, greaterOrEqual` only for Number/Currency/Percent/Date/DateTime with exactly one value (text ranges are `rollup-filter`); `contains, notContain, startsWith` only for text-family fields with at least one value. Allowed filter field types: Checkbox, Number, Currency, Percent, Date, DateTime, Text, Picklist, Email, Phone, Url, AutoNumber; everything else (TextArea, LongTextArea, Html, MultiselectPicklist, EncryptedText, Lookup, MasterDetail, Id, Time, compound, formula, another roll-up) is `rollup-filter`. Checkbox takes exactly one token `true`/`false` (case-insensitive, stored lower-case). Number tokens must be finite numbers; Date tokens `YYYY-MM-DD`; DateTime tokens ISO 8601 (`coerce.ts` DATETIME_RE pattern). A date literal token (`TODAY`, `LAST_N_DAYS:30`, i.e. `/^[A-Za-z_]+(:\d+)?$/` on a Date/DateTime filter) is `rollup-filter` with the words `date literal` (deferred).
- `valueField` accepts `Child.Field` or a bare `Field`, must be a stored field on the same child in the same type family (numeric; Date; DateTime; Checkbox; text), the `value` must be blank, and only equals/notEqual/range operators are allowed with it; anything else is `rollup-filter`.
- Resolved roll-up FieldDefs: `baseField(name, label, type, true)` + `readOnly` + `nillable: true` + `defaultedOnCreate: false` + `rollup`; `description` / `inlineHelpText` copied when present. Warnings are plain strings in buildOrgSchema's `warnings` (the CLI prints them), never console output.

Output: `resolveRollups` in `packages/metadata/src/rollup.ts`, wiring in `build.ts`, tests in `build.test.ts`.
