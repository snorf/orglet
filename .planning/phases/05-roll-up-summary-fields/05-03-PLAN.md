<objective>
Build the single roll-up SQL builder in `@orglet/schema` (shared by the engine recompute in 05-05 and
by `migrate()`), and the D-10 backfill of newly added roll-up columns.

Purpose: ROLL-03 (aggregates and filter operators over non-deleted children), ROLL-08 (the roll-up
is a real stored column, filled on upgrade), ROLL-06 (backfill orders chains bottom-up).

Planning-time decisions (do not relitigate):
- Mechanism differs from D-03's literal "`UPDATE ... LEFT JOIN`" wording but not its behaviour: correlated
  scalar subqueries per roll-up (`(SELECT COUNT(*) FROM child c WHERE c.fk = p.id AND c.isdeleted = false AND <filters>)`,
  `COALESCE((SELECT SUM(...) ...), 0)`, plain `MIN`/`MAX`). An empty child set yields 0/0/NULL/NULL exactly as the
  LEFT JOIN would (D-04), one shape serves both targeted recompute (SELECT) and full backfill (UPDATE), and FK
  columns are already indexed by ddl.ts. The engine (05-05) SELECTs first and writes per parent, because the
  parent's rules and hooks (D-01) need the prospective row before the write.
- The builder lives in `@orglet/schema`, not the engine: `migrate()` must backfill (D-10) and schema cannot import engine.
- Filter semantics (LOW-confidence items decided at planning): text comparisons are case-insensitive (`lower()`);
  multi-token `equals`/`contains`/`startsWith` OR their tokens; `notEqual` and `notContain` include NULL
  (`col IS NULL OR NOT (...)`); blank `equals` is `IS NULL` (text also `= ''`), blank `notEqual` is `IS NOT NULL`
  (text also `<> ''`); range operators never match NULL; field-to-field `equals` is `=` (NULL never matches),
  `notEqual` is `IS DISTINCT FROM`; LIKE tokens escape `\`, `%`, `_` with a backslash.
- Backfill runs with migration semantics: no hooks, no validation rules, every parent row including soft-deleted
  ones, only for columns this migrate() added (a changed operation/filter on an existing column is not
  re-backfilled; the deferred `rollup --recompute` command covers that). A table created in this run needs no
  backfill (it is empty).

Output: `packages/schema/src/rollup.ts` + tests, migrate backfill + integration test.
</objective>

    ```typescript
    /**
     * SQL for roll-up summary fields: one correlated aggregate per roll-up over the child's live rows, used
     * by the engine to recompute affected parents and by migrate() to backfill a newly added column. Pure:
     * returns SQL and parameters, executes nothing. Values are always parameters, never inlined.
     */
    import type { FieldDef, OrgSchema, RollupFilterDef, SObjectDef } from "@orglet/metadata";
    import { columnName, quote, tableName } from "./columns.js";

    export interface RollupStatement { sql: string; params: unknown[] }

    /** `SELECT p."id" AS "Id", <aggregate> AS "<Field>", ... FROM <parent> p WHERE p."id" = ANY($1) AND p."isdeleted" = false`. */
    export function rollupSelectSql(orgSchema: string, schema: OrgSchema, parent: SObjectDef, fields: FieldDef[], parentIds: string[]): RollupStatement
    /** `UPDATE <parent> AS p SET "<col>" = <aggregate>` over every row (D-10 backfill). */
    export function rollupBackfillSql(orgSchema: string, schema: OrgSchema, parent: SObjectDef, field: FieldDef): RollupStatement
    /** 0 for a plain field, 1 for a roll-up over a plain field, n + 1 for a roll-up over a depth-n roll-up. */
    export function rollupDepth(schema: OrgSchema, field: FieldDef): number
    ```

    Export from `packages/schema/src/index.ts`: `export { rollupBackfillSql, rollupDepth, rollupSelectSql } from "./rollup.js";` and `export type { RollupStatement } from "./rollup.js";`.
