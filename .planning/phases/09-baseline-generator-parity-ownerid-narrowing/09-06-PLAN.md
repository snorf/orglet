Planning-time decisions (locked decisions 4 and 5, Research Patterns 4 and 6, Pitfalls 3, 8, 9, 11):
- Rules for a field that is **new** to a v1.0 object (v1.0 fields stay exactly derived+pins+overrides, no gating, no forcing):
  1. type via TYPE_MAP; `skip` types are omitted and reported as `UNSUPPORTED:field-type <Obj>.<Field> (<source type>)`
     (existing area reused, per CLAUDE.md).
  2. reference whose `referenceTo` contains any object not in objects.json: omit the whole field, report as
     `reference-target <Obj>.<Field> -> <targets>` (keeps the loader quiet; Phase 10 adds objects additively). The whole field
     is skipped rather than dropping targets, so a polymorphic lookup never silently becomes a single-target FK.
  3. featureGated when: PDF `gating` non-empty, or `matchGating(sf-skills description)` non-empty, or the field is in sf-skills
     `ispersonaccount_fields`; overrides `featureGated: true|false` + reason wins. Gated: `featureGated: true`, never
     `nillable: false`; documented createable/updateable kept (D-09).
  4. required-looking (not Nillable, createable, not defaultedOnCreate): `nillable: false` is not written; report under
     `forcedNullable`; an overrides `set: { nillable: false }` with reason restores it.
  5. field present only in sf-skills `field_reference` (not in `fields`, not in the PDF): include read-only
     (`createable: false`, `updateable: false`), provenance `sdk-only`, reported.
  6. picklists: no values, no `restrictedPicklist` (values are per-org, Pitfall B4).
  7. labels per typemap; numeric precision/scale defaults marked `guessed`.
  8. conflicts between the sources abort in normal mode (09-04 rule). `collectConflicts: true` (used by `--report` and by
     the in-memory tests of this plan) returns them in the report instead of throwing.
- Object JSON gains `keyPrefixSource` from overrides (D-07; Phase 8 D-12). `ownerTargets` is not emitted yet (09-08).
- `CLI_OPTIONS` stays `{ v1Only: true }` in this plan; nothing under `packages/metadata/standard/` changes here.
- PDF re-snapshots during extraction fixes use `pnpm baseline:snapshot -- --pdf <cache path>` (the copy 09-03 keeps under
  `~/.cache/orglet/`, path in 09-03-SUMMARY), never a fresh download. If a re-run shows a different Last-Modified or sha256,
  that is a deliberate re-pin: it re-opens the 09-04 pins (re-run `--bootstrap-pins`, review the diff) and is raised at the
  checkpoint, not done silently.
