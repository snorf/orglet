Planning-time decisions (locked decisions 4 and 5, Research Patterns 4 and 6, Pitfalls 3, 8, 9, 11):
- Rules for a field that is **new** to a v1.0 object (v1.0 fields stay exactly derived+pins+overrides, no gating, no forcing):
  1. type via TYPE_MAP; `skip` types are omitted and reported as `UNSUPPORTED:standard-field-type <Obj>.<Field> (<token>)`.
  2. reference whose `referenceTo` contains any object not in objects.json: omit the whole field, report as
     `reference-target <Obj>.<Field> -> <targets>` (keeps the loader quiet; Phase 10 adds objects additively).
  3. featureGated when: PDF `gating` non-empty, or `matchGating(sf-skills description)` non-empty, or the field is in sf-skills
     `ispersonaccount_fields`; overrides `featureGated: true|false` + reason wins. Gated: `featureGated: true`, never
     `nillable: false`; documented createable/updateable kept (D-09).
  4. required-looking (not Nillable, createable, not defaultedOnCreate): `nillable: false` is not written; report under
     `forcedNullable`; an overrides `set: { nillable: false }` with reason restores it.
  5. field present only in sf-skills `field_reference` (not in `fields`, not in the PDF): include read-only
     (`createable: false`, `updateable: false`), provenance `sdk-only`, reported.
  6. picklists: no values, no `restrictedPicklist` (values are per-org, Pitfall B4).
  7. labels per typemap; numeric precision/scale defaults marked `guessed`.
  8. conflicts between the sources abort (09-04 rule); settle each with an overrides `set` + reason, or fix the extraction.
     Stop rule: if more than 75 unresolved conflicts appear on new fields, first look for an extraction bug (re-run
     `pnpm baseline:snapshot` after fixing snapshot-pdf.ts); if still more than 75, stop and return a checkpoint to Johan with
     counts per fact kind instead of mass-writing overrides.
- Object JSON gains `keyPrefixSource` from overrides (D-07; Phase 8 D-12 "generator labels all 35"). `ownerTargets`: not yet.
- The build.test.ts "thin: each of the 14 objects carries only Id, the system fields, ..." test is a Phase 3 contract that
  BASE2-02 deliberately supersedes: rewrite it to "thin objects keep their v1.0 fields and only gain documented ones" (v1
  names ⊆ v2 names) and record that in the SUMMARY. The "reference: ... no reference-target warning remains" test must stay green
  as-is (rule 2 guarantees it).
</objective>
