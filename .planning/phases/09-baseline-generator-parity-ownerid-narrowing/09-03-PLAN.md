<objective>
Produce the second source (D-01b): a facts-only, per-object extraction of the public Object Reference PDF, made by a
committed manual script, plus the committed gating keyword list (D-08). This is the riskiest task of the phase
(Research Pitfall 7: section boundaries, moving name column, multi-line Refers To).

Purpose: the generator (09-04+) cross-checks sf-skills against it ("verified"), gets the doc-only fields (Data.com,
Person Account), the master-detail token (MIGR-03) and gating hits from it, offline.
Output: gating.ts, snapshot-pdf.ts, `source/object-reference/<Object>.json` + VENDOR.md, a sanity test.

Planning-time decisions:
- The PDF and the raw pdftotext output live only in the scratch dir; never in the repo. The extraction keeps facts
  only (legal note, Research "Licence": MEDIUM; Johan accepted the facts-only approach in D-01).
- "Maximum size is N characters" is turned into a number (`maxLength`) at snapshot time; the sentence is discarded.
- Gating keywords in PDF prose are matched at snapshot time (the prose is not committed); sf-skills prose is matched
  by the generator at generation time with the same `matchGating`.
- Sections: locate each object by the `Field Name` / `Details` table header that follows its heading, with the TOC
  order as the section sequence; never by "last bare line before Supported Calls" alone (research's crude parser
  merged Contact/Lead neighbours and missed five objects).
</objective>

Per-field block in the PDF (layout text): field name in the left column, then labelled rows `Type`, `Properties`
(comma list), `Description` (prose, may contain "Maximum size is N characters"), and for references
`Refers To` (comma list, may wrap lines or appear as a bullet "• Refers To: X"), `Relationship Name`, `Relationship Type`
(observed tokens: `Master-detail`, `Master-Detail`, `Parent-detail`, `Primary-detail`, `Lookup`). Name column indent varies
(7 vs 8 spaces seen); find it from the `Field Name    Details` header on each page/section.

Gating keywords (D-08), as data: Person Accounts (`person account`), Data.com (`data.com`, `jigsaw`, `clean`
in the sense "Data.com Clean"), Territory Management (`territory management`, `enterprise territory`), Knowledge
(`knowledge`), Omni-Channel (`omni-channel`), Field Service (`field service`), Social (`social customer service`,
`social post`), Chatter (`chatter`), plus phrases `/available (only )?(when|if) .{1,60} (is|are) enabled/i` and
`/only (available|visible) (in|to) organizations? (that have|with) /i`.

Shape of a committed extraction file `scripts/gen-baseline/source/object-reference/<Object>.json`:
```json
{
  "object": "Account",
  "fields": {
    "AccountNumber": { "type": "string", "properties": ["Create", "Filter", "Group", "Nillable", "Sort", "Update"], "maxLength": 40 },
    "ParentId": { "type": "reference", "properties": ["Create", "Filter", "Group", "Nillable", "Sort", "Update"], "refersTo": ["Account"], "relationshipName": "Parent", "relationshipType": "lookup" },
    "PersonBirthdate": { "type": "date", "properties": ["..."], "gating": ["person-accounts"] }
  }
}
```
Rules: `type` lower-cased raw token; `properties` raw tokens as printed, sorted; `refersTo` sorted; `relationshipType`
normalised to `lookup` | `master-detail` (Master-detail/Master-Detail/Parent-detail/Primary-detail) ; keys omitted when
absent; fields sorted by code-unit order; `JSON.stringify(v, null, 2) + "\n"`.
