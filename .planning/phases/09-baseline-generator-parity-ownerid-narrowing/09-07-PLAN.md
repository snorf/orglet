- Derivation: OwnerId targets = (sf-skills `fields.OwnerId.refers_to` ∪ PDF `OwnerId.refersTo`) ∩ {User, Group}. If both sources
  name targets and the intersections differ: conflict. If no source names any target: generator error unless an override
  exists. Write `ownerTargets` only when the result is narrower than ["Group", "User"] (sorted `["User"]`), so untouched objects
  stay byte-identical. Override always wins.
- Overrides (exact reasons):
  - Event: `{ "value": ["User"], "reason": "Object Reference: Calendar, User; Calendar not modelled; widen when a Calendar object lands", "ref": "Object Reference: Event.OwnerId" }` (D-12)

  - Group: `{ "value": ["User", "Group"], "reason": "Object Reference: Organization, User; Organization not modelled and narrowing would add an FK on group.ownerid; default kept", "ref": "Object Reference: Group.OwnerId" }` (locked decision 4)
- `namePointing` in describe is left unchanged (Research: unverified, LOW).
- Custom objects keep [User, Group] (D-13); no queue-meta reading (deferred).
- The main upgrade fixture is not extended (D-14): the Group-owned Account scenario lives in its own test file, so
  `EXPECTED_WARNINGS` in upgrade.test.ts stays as 09-06 left it.
