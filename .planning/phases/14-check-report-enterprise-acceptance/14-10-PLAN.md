Report gap 3 of 14-VERIFICATION.md: on the large retrieve one formula fails on `QuoteLineItemId` of a baseline object,
an accepted standard-field exclusion (14-03, class C). The retrieve has no field file for it, so `build.ts` emits no
`UNSUPPORTED:standard-field` diagnostic and rule (2) of `groupByRoot` finds nothing to group under: the formula is
counted as its own root under `formula`. Group it under the standard-field cause instead.

Design (Claude's discretion, no CONTEXT.md; chosen to keep every existing invariant):
- `groupByRoot` gets rule (5), tried only after rules (1)-(4) found no parent: a diagnostic with `missing` whose
  `missing.object` is a modelled object with `custom === false`, whose `missing.field` is identifier-shaped without `__`
  (`/^[A-Za-z][A-Za-z0-9_]*$/` and not containing `__`, so no custom, namespaced, `$`-global or colon-typed name), and for
  which no `fieldCandidates(missing.field)` resolves via `inputs.schema.getField`, has as parent an implied root
  `{ area: "standard-field", object: <canonical object name>, field: missing.field, message: "<Object>.<field> is not in the baseline; referenced by formulas, no field file in the retrieve" }`,
  one per lower-cased object.field (memoised, so several formulas share one group).
- `RootCauseGroup` gains `implied?: true`; the implied root is not one of `diagnostics` (it prints no `warning:` line).
  Verdict math is unchanged: `dependents` counts warnings that have a root, `rootCauses = warnings - dependents`
  (warning lines that are roots), so `warnings = rootCauses + dependents` still holds. The formula's area row keeps
  `count` and gains a dependent, exactly like any other grouped formula. Area keys stay 1:1 with warning lines.
- `formatGroups` prints an implied root as `  UNSUPPORTED:standard-field <message>  [implied, N dependents]`.
- The `warning:` lines, `--summary` (no groups) and `version: 1` are untouched; `implied` is an additive JSON key.

Purpose: ACC2-03 bookkeeping (the formula then counts with the accepted standard-field exclusions) and CHECK-01
("groups cascaded formula failures under their root cause").
Output: report.ts rule (5), tests.
