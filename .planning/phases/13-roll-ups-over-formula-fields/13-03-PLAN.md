    Diagnostic key helper (module-private): `const keyOf = (area: string, object: string, field: string) => \`${area}:${object}.${field}\`;` — this is the `cause` format.

    Algorithm (loop until a round removes nothing):
    1. `schema` = current `OrgSchemaImpl`; a per-round compile cache `Map<string /* lower "obj.field" */, { deps: FormulaDependencies } | { error: FormulaCompileError }>` filled lazily by `compileField(obj, field)` = `compileFormula(field.formula, { schema, objectName: obj.name, context: "formula_field", ...(field.formulaTreatBlanksAs ? { treatBlanksAs: field.formulaTreatBlanksAs } : {}) })`; catch only `FormulaCompileError` (rethrow anything else). Compile warnings (`compiled.warnings`) are ignored here; FormulaRegistry reports them later. `lookup: FormulaLookup = (o, f) => cached deps or undefined`.
    2. Collect roll-ups in deterministic order: objects sorted by name, fields in declaration order, `field.rollup !== undefined`. For each roll-up the input names are `[rollup.summarizedField, ...rollup.filters.flatMap((f) => [f.field, f.valueField])]` filtered to defined, de-duplicated case-insensitively, in that order.
    3. Cascade rule (first, per roll-up): if any input name has no field on the child (`schema.getField(childObject, name) === undefined`) and a roll-up with that `${childObject}.${name}` was removed in an earlier round (track `removed: Map<lower "obj.field", causeKey>`), drop with `{ area: "rollup-target", kind: "rollup", object: parent.name, field: rollup field name, cause: <removed key>, message: \`${parent.name}.${field.name}: ${child.name}.${name} was skipped; field skipped\` }`.
    4. Cycle rule (D-09): DFS with white/grey/black colouring over nodes `obj.field` (lower-cased key, canonical names for printing). Edges: roll-up node -> each input field on the child that is a formula or a roll-up; formula node -> each name in its compiled deps entries with `path.length === 0` whose field on the same object is a formula or a roll-up (no edges when it did not compile). Do not start new DFS work from metadata-level roll-up -> roll-up chains alone: a cycle is reported only when it contains at least one formula node AND at least one roll-up node (pure roll-up cycles are already `rollup-cycle` from metadata; pure formula cycles are handled in step 5). For every such cycle, for each roll-up node on it, emit one diagnostic `{ area: "rollup-cycle", kind: "rollup", object, field, message: \`${obj}.${f}: roll-up summaries and formula fields read each other in a cycle (${path}); field skipped\` }` where `path` is the cycle rotated to start and end at that roll-up, nodes printed `Obj.Field` joined by ` -> `. Emit each roll-up at most once. Order: roll-ups in the deterministic order of step 2.
    5. Formula rule (D-01, D-02, D-08), for every roll-up not dropped in 3/4, for each input that is a formula field on the child (in input order), take `formulaInputs(schema, lookup, child.name, input)`. If `cycle` is set: reason `is part of a formula cycle (${cycle})`, offender = input. Otherwise check each name in `formulas` (inner first, so the innermost offender is found first) via `violation(obj, name)`:
       - compile failed -> `does not compile (${error.message})`; if `error.missing` matches a key in `removed`, set `cause` to that key
       - first deps entry with `path.length > 0` -> `reads ${entry.path.join(".")}.${entry.fields[0] ?? ""} (cross-object)`

       - a global not in CONSTANT_GLOBALS -> `uses ${g}`
       First violation wins. Message: offender === input ? \`${parent.name}.${field.name}: ${child.name}.${input} ${reason}; field skipped\` : \`${parent.name}.${field.name}: ${child.name}.${input} ${reason} via ${child.name}.${offender}; field skipped\`. Area `rollup-formula`, kind `rollup`, `object: parent.name`, `field: field.name`, plus `cause` when set. Use canonical field names (from `schema.getField`).
    6. Push every diagnostic of the round through `pushDiagnostic(sink, ... satisfies SkippedItem)` in the order cascade, cycle, formula; record each removed roll-up in `removed` with its own key (`keyOf(area, parent.name, field.name)`).
    7. If the round removed anything: build new objects `new Map([...schema.objects].map(([k, o]) => [k, removedOnObject ? { ...o, fields: o.fields.filter((f) => !removedSet.has(...)) } : o]))` and `schema = new OrgSchemaImpl(objects, schema.globalValueSets, schema.standardValueSets, schema.labels)`; loop. Never mutate the input `SObjectDef`s or arrays.
